### Learnings for future iterations
- **A doc gate must trigger on the ACT that staleness enters by, not only on the doc.** Gating
  `ROADMAP.md` edits alone would be circular — the roadmap goes stale when a *tasklist retires*, an
  event that touches `tasks/chief/completed/` and never touches the roadmap. That path is now in
  both triggers. Generalise: ask "what commit makes this doc wrong?" and gate *that*.
- **`shellcheck` is absent on this machine but reachable with zero install:**
  `npx --yes shellcheck@latest -S error …` downloads a real binary and caches it under
  `~/.npm/_npx/`. Worth the ~40s for CI parity. And when it flags files you didn't touch,
  `git show main:<file> | shellcheck` proves pre-existing in one command — do that before
  "fixing" someone else's file inside your story.
- **The version-claim helper had to be extracted, not copy-pasted.** `CHIEF_QUALITY_TOL_duplicate_blocks`
  is **0** at a 6-line window, so duplicating the ~8-line README version check for the ROADMAP would
  have blocked the merge on the ratchet. Extracting it also kept `function_length_mean` inside tol 5
  (this file's only prior function is the 1-line `fail()`, so the base mean is 1 and a big new
  function moves the mean hard — keep an added helper ≲12 lines in a file this small).
- **Bumping `VERSION` in this repo is now a THREE-file edit**, not two: `VERSION`, README's bold
  `**vX.Y.Z**`, and ROADMAP's. That is the new gate working as intended, and it bit on this very
  story (0.9.1 → 0.9.2 failed doc-sync until the roadmap moved too).
