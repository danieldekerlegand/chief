## Codebase Patterns

- **A new `test/*.sh` is a gate only in THREE lists** (already in CLAUDE.md, restating
  because this tasklist hit it): `.chief/verify.sh`'s `CHIEF_BYSTANDER_TESTS`,
  `test/all.sh`'s `BASH_SUITE`, and `.github/workflows/ci.yml`.
- **`usage()` in `bin/chief` is the repo's longest function (192 lines on main) and it
  therefore OWNS `function_length_max`.** The ratchet's tolerance is 15 lines, so a
  usage entry longer than ~14 lines blocks the merge on its own — and the next story
  on the same branch measures against the SAME base, so every usage edit on a branch
  shares one 15-line budget. Write the entry compact the first time.
- **A `gh run list` fake is enough to test a CI probe hermetically.** Two calls are all
  `engine/cigate.sh` makes (`run list`, `run view --json jobs`); a ~15-line fake `gh` on
  PATH serving fixture JSON keyed by `--repo <slug>` covers every case, and a missing
  fixture exits 1, which is exactly what an offline/unauthenticated `gh` does.
- **Narrowing `PATH` to `/usr/bin:/bin` to simulate "tool absent" is a trap** — it also
  drops tools the code legitimately needs, so the test can pass for the wrong reason.
  Build a dir of symlinks to everything the code needs EXCEPT the one tool under test.

## US-1 — A declared gate that never ran is reported, not assumed  (2026-08-26)

Added `engine/cigate.sh` and the `chief cigate` subcommand.

Files: `engine/cigate.sh` (new), `test/cigate.sh` (new), `bin/chief` (usage entry,
`cmd_cigate`, dispatch arm), `.chief/verify.sh` + `test/all.sh` +
`.github/workflows/ci.yml` (register the test), `README.md` (command-table row +
version), `ROADMAP.md` (version), `VERSION` 0.9.2 -> 0.9.3.

What it does: for each `.github/workflows/*.yml|*.yaml` a repo DECLARES, it reports the
state of that workflow's most recent run — `RAN AND PASSED` / `RAN AND FAILED` /
`DID NOT RUN` / `UNKNOWN` / `NO GATE DECLARED`. `DID NOT RUN` covers three shapes: no
run ever recorded, a run that completed without executing a single step, and a green
run that never covered the commit asked about (`--head` / `--sha`).

**The measurement that made the "failed to start" case checkable.** A billing-blocked
run completes in ~4s with jobs present, `conclusion: failure`, and `steps: []` on every
job (cuneiform run 32944778403). A run that really executed has a populated `steps`
array (pinakes run 32827758461: 10). So "at least one step recorded anywhere in the
run" is the discriminator, and it is measured, not inferred from the conclusion string.

**A real bug the counterfactual caught.** Matching a declared workflow to its runs by
`name:` alone LOSES exactly the case this module exists for: when GitHub cannot parse
the workflow file at that ref it reports the run under `.github/workflows/ci.yml`
rather than the declared `name: ci` — so chief's own dead gate read as "no run ever
recorded" instead of "never started". The matcher accepts the declared name OR the
file path.

Observed on the real portfolio: cuneiform 11/11 DID NOT RUN, vita 1/1 DID NOT RUN,
chief 1/1 DID NOT RUN, praxis RAN AND PASSED, pinakes 3 passed / 2 failed / 1 never
run. That reproduces the 2026-08-25 measurement in the tasklist description.

Gates: `test/cigate.sh` PASS, `smoke` PASS, `ratelimit` PASS, `noworkguard` PASS,
`version-bump` PASS, `doc-sync` PASS, `bash -n` clean, doc-links 0 dead vs 0 on main,

### Learnings for future iterations

- The state vocabulary is already stated once, in `engine/cigate.sh`'s
  `CIGATE_PASSED/FAILED/DEAD/UNKNOWN/NONE` + `cigate_label`. **US-3 must reuse those,
  not invent a second set** — that is most of its first acceptance criterion.
- `cigate_scan REPO [SHA]` is the one entry point; it already takes the commit the
  verdict is about, which is what US-3's merge record needs.
- `cigate_workflow_name FILE` is textual (`sed`, no YAML dependency) and returns the
  path when the file declares no `name:` — US-2's trigger check should extend that same
  textual reader rather than add a parser.
- `cigate_classify` is a PURE function of (slug, one run record, sha) apart from the
  jobs probe, which is why the fixtures can drive every branch of it.
