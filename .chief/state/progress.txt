# Chief Progress — 112-a-bookkeeping-commit-is-not-progress
Started: Wed Aug 26 11:52:01 CDT 2026

## Codebase Patterns

- **The iteration-outcome classifier lives in ONE block** — `engine/agent.sh`, right after
  `_measure_boundary`/`_prd_promote`: `now_pass=$(_passes); now_head=$(_head)` and the
  if/else that either resets `stall` or increments it. Every "chief scored this iteration
  wrong" bug (111, 112) ends up in that block or in the guards immediately above it
  (rate limit, `_is_no_turn`), which are placed BEFORE it precisely because they are not
  judgements about the work.
- **A behavioural test must REPRODUCE before it is trusted.** The cheap way here: `git clone
  --no-local` this worktree to a temp dir, revert the one line under test in the clone,
  commit, and run the same test file there — the suite installs chief from
  `git rev-parse HEAD` of its own `$ROOT`, so the clone tests the neutered engine with no
  risk to this tree. (`git show HEAD~N` does not work in CI: the clones are shallow.)
- **`cmd | grep -q` under `set -o pipefail` is a length-dependent assertion.** `grep -q`
  exits on the first match and SIGPIPEs the producer, so the pipeline fails when the input
  is long and passes when it is short. Every test in this suite that greps a `git log`
  should capture into a variable first and `case` on it — a fixture whose whole point is
  "the loop ran 20 times instead of 2" will otherwise fail on the wrong assertion.

## US-1 — Progress means a story moved or the PRODUCT changed

`engine/agent.sh`:
- `_product_changed PREV NOW` (beside `_passed_ids`) — true when the net tree diff
  `git diff --name-only PREV NOW` touches at least one path outside `$BOOKKEEPING_REL`
  (`${CHIEF_STATE_DIR:-.chief/state}/`). TREE-to-TREE, so an amend/squash landing on an
  identical tree is not progress; and the commit MESSAGE is never read. FAILS OPEN on
  anything it cannot answer (unknown sha, `none`, git error) — the old behaviour was "any
  HEAD move is progress", and an unreadable diff must not become a silent way to stall a
  working run. In a `repo:<sub>` worktree the state dir is not in the tree at all, so no
  path matches the prefix and every commit counts, which is correct there.
- The progress check now reads `[ "$now_pass" -gt "$prev_pass" ] || _product_changed ...`,
  and the stall branch says `no progress — BOOKKEEPING ONLY (...)` when HEAD moved anyway,
  so an operator reading `git log` beside the run does not think chief lost the commit.

`test/bookkeeping-progress.sh` (new; registered in all THREE lists — `.chief/verify.sh`'s
`CHIEF_BYSTANDER_TESTS`, `test/all.sh`'s `BASH_SUITE`, `.github/workflows/ci.yml`):
replays the formant shape — every turn re-stamps `notes` in the runtime prd.json, appends
to progress.txt, `git add -f`s both (chief init gitignores `.chief/state/`) and commits
`feat: US-1 - record the re-check and the blocker`. Asserts the fixture really is
state-only first, then that the run takes exactly `iters` (2) turns.

## Learnings for future iterations

- **US-2 has a ready-made home**: add a `bk-both` tasklist to `test/bookkeeping-progress.sh`
  whose agent does real work AND stamps state in the same turn, and assert it scores as
  progress. The fixture, the install and the assertions are already there.
- **US-3's line is `Iteration $i: progress ($now_pass/$(_total) passing). Continuing...`**,
  still exactly as it was — US-1 deliberately left it alone. Note that
  `test/boundary-demotion.sh` greps `Iteration 2: progress` and `Iteration 2: no progress`,
  so keep those two prefixes whatever the rest of the sentence becomes.
- **This repo's own `tasks/chief/*.json` omit `passes` entirely** (the generator writes
  `notes: null` and no flag). `_passes()` counts `passes==true` so the count is right, but
  `_story()` selects `.passes==false` and therefore returns EMPTY for a freshly generated
  tasklist — the liveliness record's `story` field is blank until an agent writes a flag.
  Pre-existing, not touched here, but it is why `chief ps` shows no story id early in a run.
- **`.chief/state/prd.json` and `progress.txt` are TRACKED in chief's own repo** (added
  before `.gitignore` gained `.chief/state/`), so chief self-hosting is exactly the repo
  where the formant pathology can occur — `git log --oneline -- .chief/state` shows
  `chore: driver-seeded run state` commits. That is the case US-2 must keep working.
