## Codebase Patterns

- **A new agent.sh exit code is ~8 edit sites, and they are all findable from one
  grep.** `grep -n 'AGENT_RC_LIMIT\|RATE-LIMITED\|rate-limited'` across `engine/` gives
  the complete list: agent.sh's exit-code header + the loop arm; driver.sh's
  `AGENT_RC_*` constant, its `run_worker` arm (**above** the EMPTY-NO-WORK guard),
  `tasklist_outcome`, `reap()`, the summary accumulator + block, and the headless
  `hl_*` mapping; plus live.sh's state/phase vocabulary comments and monitor.sh's
  `glyph_for` + `STALE_QUIET_PHASES`. Model the whole thing on `RATE-LIMITED` — it is
  the closest existing shape (a non-failure block that keeps branch + worktree).
- **`test/stall-flag.sh` is a DRIFT GUARD on the phase vocabulary.** Any new
  `live_set … phase=<x>` literal in `engine/` must be classified in exactly one of its
  `QUIET_PHASES` / `FLAGGED_PHASES` lists or the test fails by name. That is the point:
  "a new state classified nowhere is exactly how a false stall gets reintroduced."
- **Braces around any `$var` butted against a multibyte character — in TESTS too.**
  `"$iter2× — …"` made bash read the `×` bytes as part of the identifier and die under
  `set -u` with `iter2\xd7: unbound variable`. `${iter2}×` fixes it. CLAUDE.md records
  this for em-dashes in the engine; it bit a test on a `×` here.
- **`shellcheck` is installable without brew.** `curl -fsSL
  https://github.com/koalaman/shellcheck/releases/download/v0.10.0/shellcheck-v0.10.0.darwin.aarch64.tar.xz`
  → a standalone binary. Note 0.10.0 flags 3 errors in `engine/quality.sh` +
  `engine/sweep.sh` that are **pre-existing on `main`** (CI's version does not), so
  scope the check to the files you touched.

## US-1 — An iteration that never reached the model does not count as an attempt

**What was wrong.** `_is_rate_limit` was the only pre-accounting classifier, so a
`529 Overloaded` fell straight through to the progress/stall check, was scored
"no progress", and tripped `stall 3/2`. The stall counter answers "is the agent
getting anywhere" — a refused request is not an answer to it.

**The shape of the fix.** A second classifier in the same window, `_is_no_turn`,
requiring THREE facts: the provider exited non-zero, the invocation left no trace
(HEAD unmoved + no story flipped, read off the branch at the call site), and the
failure names itself as a request-level refusal (a status code or an error type out
of the provider's own envelope; text arms only when there is no structure at all,
and those are a dated observation list). A refused iteration is rolled back
(`i=$((i-1))`, the `_rate_limit_wait` idiom) so it charges nothing; a consecutive
counter `PROVIDER_NOTURN_LIMIT` (default 3) bounds it, because a stop that costs no
budget also ends no run. Exit 8 → `PROVIDER-UNAVAILABLE`, scheduler state
`provider-unavailable`, reported with the other holds and never among the failures.

**Files:** `engine/agent.sh` (config + `_provider_status_code` / `_provider_error_type`
/ `_is_no_turn` / `_noturn_reason` / `_provider_unavailable` + the loop arm),
`engine/driver.sh` (`AGENT_RC_UNAVAILABLE`, the run_worker arm, outcome/reap/summary/
headless), `engine/monitor.sh`, `engine/live.sh`, `test/provider-unavailable.sh` (new,
registered in verify.sh + all.sh + ci.yml), `test/stall-flag.sh`,
`docs/reference/provider-unavailability.md` (new) + README/events/headless/providers
docs, `VERSION` 0.8.88→0.8.89.

**Learnings for future iterations.**
- `overloaded_error` was moved OUT of `RATE_LIMIT_STATUS_PATTERN`. It was latent
  breakage: a structured 529 matched the limit path, whose reset parser finds nothing
  in an overload and falls back to sleeping `RATE_LIMIT_WAIT` — an hour. If US-2 needs
  to route something between the two paths, the fork is `_is_rate_limit` first (there
  is a window to wait out), `_is_no_turn` second.
- **The hook US-2 lands on is `_provider_unavailable`.** It is the single decision
  point ("retry or stop") and already writes the live record + event + the
  `$NOTURN_FILE` reason the driver reports. Backoff/`Retry-After` goes inside it; the
  `sleep 2` before the `continue` at the call site is a placeholder for exactly that.
  `_is_no_turn` already separates 5xx/529/transport from 401/402/403, so US-2's
  transient-vs-permanent split has its classifier — it needs the ACTION, not new
  detection.
- **US-3's reporting hook is the same file the driver already reads.** `run_worker`'s
  exit-8 arm writes `$STATE/<name>.unavailable`; the INCOMPLETE arm two blocks below
  is where the `git status --porcelain` count belongs, and `.chief/state/parallel/<n>.status`
  is what `chief ps` renders from.
- The test's Part 2 is the one worth copying: assert the PAIR in one run. A test that
  only pins the new classification cannot show the two are told apart, which is
  literally what the acceptance criterion asked for.
