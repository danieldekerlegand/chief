## Learnings for future iterations

- **A green `test/*.sh` is not evidence the ENGINE is green — bisect the engine, not
  the test.** `git archive <ref> | tar -x -C /tmp/chief-<ref>` gives a throwaway ROOT,
  and every hermetic test here takes its engine from `ROOT="$(cd "$(dirname
  "${BASH_SOURCE[0]}")/.." && pwd)"`. Copy the test to /tmp, pin `ROOT=` to the export
  and neuter its `trap ... rm -rf "$WORK"` to `echo "WORK=$WORK"` — now the same
  fixture can be run against main, against the old base, and against the branch, and
  "did this branch break it" stops being an argument and becomes a measurement.
- **A behavioural test that races real workers may have been passing for the wrong
  reason.** PART D's ordering assumption only ever held because the machine budget bug
  serialized every agent turn. Fixing a CONCURRENCY bug retroactively un-fixes every
  test whose determinism was quietly resting on the absence of concurrency — expect a
  crop of them, and read a newly-red test as "what did parallelism just expose" before
  reading it as "what did I break".
- **In `test/merge-batch.sh` the verify counter is keyed by `basename "$PWD"`,** so the
  merge-gate runs land in `$OZ_WORK/<repo>.verifies` and the band-110 agent-side
  pre-completion runs land in `$OZ_WORK/<tasklist>.verifies`. Two different counters,
  which is why the exact `verifies == 5` assertions still model only the merge gate.
- **The run's own event stream is the timing oracle.**
  `jq -r 'select(.event=="tasklist.queued")|[.ts,.name]|@tsv'` over
  `$CHIEF_RUNS/<run-id>.events.jsonl` reads out enqueue order and the real margins
  between workers — far better than inferring order from a worker log with no
  per-line timestamps.
