## US-5 — A hold record does not outlive the branch it holds
Implemented durable overlap-record cleanup through `zones_clear_record`, used at the successful merge/retire/reap site. `chief approve --list` now resolves the recorded branch and base before rendering: deleted refs and branches already contained in the base are reported as STALE and both request and approval files are dropped; live unmerged branches remain actionable. Added adversarial coverage for deleted, already-merged, and genuinely pending records in `test/overlap-zones.sh`; bumped VERSION/README to 0.8.88.

Learnings for future iterations: approval records must be treated as a request/verdict pair and validated against git refs before being presented as an action. A pending branch is only safe to retain when its ref exists and is not an ancestor of the recorded base.
